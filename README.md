面向法律检索、实证研究、LegalNLP 语料构建等用途。

## judgments.jsonl 字段

| 字段 | 含义 |
| --- | --- |
| `case_name` | 书中案件名（索引缩略名） |
| `category` | 原书分类 |
| `book_pages` | 该案在原书正文中出现的页码 |
| `matched_title` | 在北大法宝匹配到的裁判文书正式标题 |
| `pkulaw_url` | 该文书在北大法宝的链接 |
| `doc_type` | 文书类型、法院、案号、审结日期 |
| `match_score` | 名称匹配置信度 |
| `fulltext` | 判决书全文（未命中者为空串） |

### 用法

```python
import json

with open("data/judgments.jsonl", encoding="utf-8") as f:
    cases = [json.loads(line) for line in f]

hits = [c for c in cases if c["fulltext"]]
print(len(cases), "个案件，", len(hits), "篇有全文")

# 查看某案
c = hits[0]
print(c["case_name"], "->", c["matched_title"], c["pkulaw_url"])
print(c["fulltext"][:500])
```

```bash
# 只看有全文的记录，导出为纯文本
jq -r 'select(.fulltext != "") | "### \(.case_name)\n\(.fulltext)\n"' data/judgments.jsonl > all.txt
```

## 数据来源与生成方法

**1. 案件索引** —— 原书《案例索引》位于原书第 736–756 页（PDF 第 763–783 页，二者相差 27 页）。该书为**扫描版 PDF、无文本层**（仅有一层引流水印文字），使用 macOS Vision 框架（`zh-Hans`，Accurate 模式）OCR，并依据识别框坐标还原多栏与换行排版。

**2. 判决书全文** —— 通过本机 Chrome（CDP 协议自动化）访问北大法宝司法案例库检索抓取：

- 采用**标题检索**（比全文检索精准得多）
- 匹配规则：原告名完整出现且后接边界字（诉/与/不服/状告/等/申请…），**或**与标题的最长公共子串 ≥4 字且不含通用词，**且**结果须为行政案件
- 文书详情页必须**从检索结果点击进入**（直接跳转 URL 会被拦截返回空壳）
- 全程限速，多标签页并行，单账号常态访问

## 已知局限

- **书中案件名是索引缩略名**（如"苏州爱利电器公司诉苏州市工商局沧浪分局行政处罚案"），与裁判文书正式标题常有较大差异；年代较早或未公开的案件往往无法匹配。67% 的命中率是"宁可漏、不可错配"的结果。
- 少数结果可能仍为同名当事人的其他案件；`match_score`、`matched_title`、`doc_type` 可供人工复核，`data/pkulaw_results.json` 中另存有被否决的候选（`rejected_match`）。
- OCR 可能存在个别形近字误差。
- `book_pages` 是**原书正文页码**，不是 PDF 页码。
